# Customer templates

The messages an agent product owes its customers that a conventional product never had to send. Each one is fed by the [ledger](../../ledger.md). None of them is a newsletter. Each fires on an event, says one true thing, and asks for at most one decision.

| Template | Fires when | Delight form |
|---|---|---|
| [Receipt](receipt.md) | The work went well and nobody looked | Make the invisible work visible |
| [Promotion offer](promotion-offer.md) | A class has a record strong enough for the next rung | The next rung, offered as a gift |
| [Correction landed](correction-landed.md) | A correction the customer made has been applied | The correction that visibly landed |
| [Prepared, not done](prepared-not-done.md) | The agent could do more than it is allowed to | Prepared, not done |
| [Held back](held-back.md) | The agent declined or a check stopped it, and the customer should know | Restraint |
| [Incident note](incident-note.md) | The agent did harm, or might have | Naming the mistake first |
| [Demotion notice](demotion-notice.md) | A rung dropped | Naming the mistake first |
| [Forwardable value note](value-note.md) | Before a renewal, or after a milestone | Making the champion look good |

The forms are described in [`floor/delight/PHILOSOPHY.md`](../../floor/delight/PHILOSOPHY.md).

## Rules for every template

- **One ledger fact or more, cited.** Every number in the message is a query over rows a person on the team can open. On a ledger below level 4, say how the number was counted ("from the 40 we reviewed together").
- **Their outcome, their words.** Name the work in the language of the desired outcome they stated, not the class name.
- **One decision at most.** A message that asks two things gets neither answered.
- **Sent by the agent unless the table says a person.** Incident notes at severity 1 or 2, demotions, and value notes come from a named person.
- **Never above the current rung.** A template may offer a higher rung. It never acts as if one were granted.
- **Write it back.** Every send is a touch in the customer's file, and delight history if it was a gesture.
